# Улучшения в VS Code относительно master

Сравниваются `port/master-features` и база upstream master
[`33835879`](https://github.com/ocaml/ocaml-lsp/commit/33835879e864a8076f95d832b49c0211adfa229c)
(OCaml-LSP 1.28.0). Эта ветка рассчитана на **OCaml 5.5 / Merlin 5.9**.
Сравнение относится к этой базе, а не к будущим изменениям master.

В VS Code используется существующее расширение **OCaml Platform**. Менять его
код не требуется. Названия действий ниже приведены без сочетаний клавиш:
они зависят от системы и настроек пользователя. Поведение сверено с кодом
и тестами сервера; это не отчёт о ручном тестировании интерфейса редактора.

## Установка и запуск через opam pin

Выполните в switch проекта с **OCaml 5.5**. Для текущего локального checkout:

```sh
opam pin add -y --kind=path --with-version=1.28.0 /home/vprekel/ocaml-lsp
```

Замените путь, если репозиторий находится в другом каталоге. Повторная команда
подхватывает изменения локальных исходников и при необходимости пересобирает
сервер. Команда фиксирует пакеты checkout вместе, включая сервер, `lsp` и
`jsonrpc`, на общей версии `1.28.0`. Поэтому точные версии этих библиотек
не требуется отдельно искать в opam-репозитории.

Для установки ветки `port/master-features` из форка и последующих обновлений:

```sh
opam pin add -y --with-version=1.28.0 \
  'git+https://github.com/prekel/ocaml-lsp.git#port/master-features'
```

Синтаксис pin описан в [руководстве opam](https://opam.ocaml.org/doc/man/opam-pin.html).

В VS Code выберите switch через **OCaml: Select a Sandbox for this Workspace**
(`ocaml.select-sandbox`), затем выполните **OCaml: Restart Language Server**
(`ocaml.server.restart`). Эти команды объявлены в
[OCaml Platform](https://github.com/ocamllabs/vscode-ocaml-platform/blob/master/package.json).
Сервер запускает расширение; отдельный запуск `ocamllsp` в терминале не нужен.

Для межфайловых ссылок и call hierarchy сначала соберите аннотации проекта:

```sh
dune build @check
```

Повторяйте сборку после изменения закрытых файлов или экспортируемых интерфейсов.
Сервер учитывает открытые несохранённые буферы, но сам сборку не запускает.

## Что меняется в редакторе

| Действие или функция | В master `33835879` | В этой ветке |
| --- | --- | --- |
| **Go to Definition / Ctrl+клик** | Locate предпочитает `.ml`, обычно возвращает точку. | Предпочитает `.mli`; для известного обычного объявления в интерфейсе повторный переход открывает `.ml`. Уточняет полное имя и учитывает известные несохранённые изменения цели. |
| **Go to Declaration** | Уже предпочитает `.mli`. | Дополнительно уточняет диапазон имени, проверяет свежесть источника и перемещает известные объявления в несохранённой цели. |
| **Go to Type Definition** | Уже поддерживается. | Уточняется диапазон имени типа, включая закрытые и сгенерированные исходники, когда цель можно определить достоверно. |
| **Go to Implementation** | Уже поддерживаются реализации типов, в том числе объявленных в `.mli`, через Smart Locate. | Добавлены значения и модули, алиасы, `include`, результаты функторов и открытые несохранённые реализации. Современный поиск типов сохранён. |
| **Find All References** | Уже есть проектные references через Merlin/project occurrences и индекс `@ocaml-index`. | Добавлен собственный индекс `.cmt`/`.cmti`, выбор нужных compiler units и их импортёров, overlays открытых буферов и проверка свежести. Нативный механизм master сохранён как fallback. |
| **Find All References из установленной библиотеки** | Нет добавленного здесь восстановления связей для перемещённых установленных исходников. | Объявление в установленном `.ml`/`.mli` связывается с использованиями в workspace по совместимым аннотациям выбранного модуля. Весь switch не сканируется. |
| **Show Call Hierarchy → Incoming / Outgoing Calls** | Запросы не поддерживаются. | Добавлены статически разрешимые вызывающие и вызываемые функции, места вызовов, рекурсия, локальные функции, частичные применения и стандартные `\|>`/`@@`. |
| **Переходы в generated sources** | Нет добавленного здесь восстановления пути к исходнику в build-контексте. | Definition, Declaration и Type Definition могут открыть существующие `.ml`/`.mli` в `_build/<context>/…`; оригинальные и promoted-копии предпочитаются. |
| **Просмотр исходников установленных библиотек** | Нет отдельного режима восстановления их окружения. | По совместимым `.cmt`/`.cmti` восстанавливаются имя модуля, implicit opens и зависимости; диагностики для распознанных установленных исходников подавляются. Hover, подсветка и навигация используют доступные сведения. |
| **Go to Definition / Declaration в `dune`** | Нет специализированного разрешения ссылок конфигурации Dune. | Переходы к локальным библиотекам, PPX, модулям, файлам, alias/rule-объявлениям, установленным пакетам и существующим generated targets. Учитываются несохранённые Dune-буферы. |
| **Подсветка локальных зависимостей в `dune`** | Нет таких semantic tokens. | Разрешённые локальные библиотеки получают `namespace`, PPX — `macro`, с дополнительным модификатором `duneLocal`. Установленные и неизвестные имена дополнительно не подсвечиваются. |
| **Hover на PPX и Show generated code** | Нет добавленного здесь просмотра expansion и deriving-сигнатур. | Hover показывает доступную сгенерированную сигнатуру; Code Action **Show generated code** открывает снимок expansion в `.ml`/`.mli`. Поддерживаются атрибуты и extension points, для которых есть результат PPX. |
| **Hover, CodeLens, Inlay Hints рядом с PPX** | Нет добавленной здесь фильтрации по исходному AST. | Сгенерированные узлы с повторно использованными исходными позициями отфильтровываются; подсказки относятся к написанному пользователем коду. |
| **Создание/обновление интерфейса через inferIntf** | Есть вывод интерфейса. | Результат форматируется с настройками проекта, если найдена `.ocamlformat`; при недоступном форматтере остаётся исходный вывод. |
| **Format Selection** | Range formatting уже поддерживается. | Явное выделение можно форматировать и в игнорируемом OCaml-файле, сохраняя настройки проекта, окружающие пробелы и точный диапазон правки. Пустое выделение не меняет документ. |
| **Extract / Inline / Combine cases / аннотации типов** | Эти действия уже существуют, включая поддержку выделений и ленивое разрешение Code Actions. | Добавлены проверки области видимости, границ выделения, порядка и количества вычислений, идентичности выделяемых объектов; combine cases использует AST. Небезопасные преобразования отклоняются. |
| **Причины недоступности рефакторингов** | Нет добавленных здесь объяснений для этих отказов. | Поддерживающий `disabledSupport` клиент получает причину недоступности; для остальных клиентов действие скрывается. |

## Условия и ограничения

Навигация уточняет только достоверные цели: неоднозначные конструкции могут
остаться точкой или не дать перехода. Изменённые закрытые файлы с устаревшими
аннотациями пропускаются. Call hierarchy не анализирует поток значений через
callback-параметры и динамический вызов методов; после изменения снимка её
нужно подготовить заново. Implementation не ищет все структурно подходящие
модули и классы.

Dune-навигация читает конфигурацию по синтаксису, без вычисления build graph.
Она не выполняет команды правил, переменные, globs или сборку. Для перехода к
установленному пакету используется `ocamlfind` из окружения сервера.

Для оформления локальных Dune-зависимостей можно перенести
[пример настроек VS Code](vscode-dune-navigation.settings.json) в настройки
редактора. Цвета и подчёркивания выбирает тема/клиент. Показ expansion требует
поддержки открытия документа (`window/showDocument`), а сам результат доступен
только после успешной обработки соответствующего PPX.

Completion, Document Symbols, обычные OCaml semantic tokens, Format Document,
Rename, базовые hover/hints/CodeLens, range formatting и проектные references
уже были в master. Исправления старой ветки 4.14 для rename, selection ranges,
фильтрации hints и запуска форматтера не считаются новыми преимуществами этой
ветки над master. Project-wide Rename и изоляция PPX этой веткой не добавлены.
