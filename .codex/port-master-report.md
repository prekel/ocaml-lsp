## Насколько помог MCP/LSP

Помощь была заметной для навигации по API и проверки поведения работающего сервера.
Большинство механических несовместимостей при переходе 4.14 → 5.5 находились
компилятором и поиском по исходникам. LSP не заменил runtime и регрессионные тесты.

| Использование | Что помогло / что не сработало |
| --- | --- |
| Hover `Position.compare` | Показал возврат `int`, позволил правильно заменить старые сравнения через `Ordering`. |
| Type Definition для Typedtree | Привёл в установленный `typedtree.mli`; полезен при адаптации новых форм функций, локальных структурных элементов и аргументов. |
| Hover `Locate.from_path` | Показал новый config/local_defs и структурированный результат Locate — существенная помощь при переносе навигации. |
| Definition `Project_snapshot.run` | Hover работал, Definition возвращал null. Именно реальная проверка через MCP выявила неверную проверку provenance: MD5 старой ветки вместо BLAKE2b-128 OCaml 5.5. Исправлено в трёх модулях. |
| References | Финальный запрос возвращает пять позиций, включая `.ml`, `.mli` и закрытые файлы вызывающих модулей. |
| Type Definition | Для выражения `state` работает; запрос непосредственно на record label `reference_index` возвращает null. Это оставшееся ограничение, а не успешная проверка. |
| Document Symbols | Возвращает 38 символов `navigation_syntax.ml`; полезен для просмотра структуры. |
| Неправильная позиция запроса | Один запрос вышел за длину строки. Исправлен вызов; это ошибка вызывающего, не LSP. |
| Диагностики | В MCP-обёртке нет отдельного инструмента диагностик. Ошибки сборки проверялись через Dune. |

Другие существенные исправления нашлись тестами: полные declaration anchors
в новом `cmt_uid_to_decl`, повторное выполнение PPX при уточнении Implementation,
подавление уже запланированных диагностик установленных библиотек и пути PPX
fixtures в sandbox Dune 3.24. Hover сам по себе их не обнаруживал.

### Исправления MCP-обёртки

Обёртка `/home/vprekel/.local/share/ocaml-lsp-mcp/server.py` теперь принимает
`--switch` независимо от `--root` и проверяет inode/размер/mtime установленного
бинарника перед запросом. После `dune install` она перезапускает LSP и сбрасывает
открытые документы. Проверены фактические смены PID после установки.

Встроенные инструменты текущего чата оставались привязаны к исходному worktree.
Для новой ветки использовалась отдельная настоящая MCP stdio-сессия той же
обёртки, запущенная с новым root/switch. Это не подмена корня встроенных инструментов.
Конфигурация нового worktree находится в `.codex/config.toml`.

Резервная копия обёртки: `.codex/reports/master-port/mcp-server.before.py`.
Изменение обёртки локальное, оно не входит в коммиты репозитория OCaml-LSP.

## Перестановка worktree после переноса

По следующему запросу пользователя ветки поменяны местами:

- `/home/vprekel/ocaml-lsp` — `port/master-features`, OCaml 5.5.
- `/home/vprekel/ocaml-lsp-port-master` — `fix/4.14-code-actions`, OCaml 4.14.

Отчёт и журнал перенесены в `.codex` основного worktree. Предыдущие разделы
описывают расположение во время переноса. Старые `_opam` и `_build` сохранены
в `/home/vprekel/.cache/ocaml-lsp-worktree-swap-20261029`; пакеты экспортированы
в `.codex/reports/worktree-swap/`. Новые switch восстановлены на правильных
префиксах из экспортов, чтобы избежать сломанных абсолютных путей.

После перестановки проверено:

- Основной worktree: `@install`, `@check`, `@all` и все 17 выбранных групп тестов проходят; `dune install` выполнен.
- Worktree 4.14: `@install`, `@check` проходят; `dune install` выполнен. При пересборке компилятора с новым GCC использован `CFLAGS=-O2 -std=gnu11`. Состав пакетов восстановлен из экспорта; три opam pin перенаправлены на новое расположение ветки 4.14.
- Обе новые MCP stdio-сессии: Hover, Definition, Type Definition и Document Symbols работают; References возвращает пять позиций после `dune build @check`.
- Бинарники сообщают `1.28.0-5-g3695ef3` и `1.21.0-4.14-41-gd4be297`.
- Отслеживаемые файлы обеих веток не изменены. Новые коммиты при перестановке не создавались.
- Логи перестановки и свежие ответы MCP: `.codex/reports/worktree-swap/`.

Встроенное MCP-подключение уже открытого чата держит процесс обёртки, запущенный
до добавления автоматического перезапуска бинарника. Он всё ещё использует старый
сервер 4.14 и требует перезапуска MCP-подключения. Конфигурация на диске корректна;
свежая MCP-сессия в основном worktree использует проверенную версию 5.5.
